# 采购成本与现金流风险管理改造

本次仅实施第一阶段保护：预测事件默认退出仓位评分；未来时间戳事件不参与评分或去重；报告侧事件继承调用方时刻；删除固定 Sep 26 合约提示。现有供给、政策等规则仍然生效，65% 基准未被认定为合适的企业政策。

## 待验证问题

- ML、LLM 与情景方向映射目前使用逆向调整；明确业务语义并完成样本外验证前不得启用预测调整。
- Brier 仍使用均匀基准；需增加默认概率与仅使用过去数据的历史频率基准。8 个样本不能认定稳定技能。
- apply_shrink 当前以 w 作为原预测权重，w=0.2 对应历史基准占80%；需要明确参数语义及重新验证权重，不能直接交换系数。
- 情景类别实际标签与区间应分别核验；统一为第五个交易日收盘收益，并冻结发布时阈值。
- 时间过滤依据现有 event.timestamp；尚不等于证明所有源数据具有可靠的公开可用时间。

## 后续开发验收

1. 采购批次：计划量、已定价量、定价期限、币种、定价基准与已有对冲；对冲剩余未定价敞口，零敞口不新增多头。
2. 企业政策：显式审批基础比例与预测调整上限；未配置政策时不生成可执行指令。
3. 执行：按合约月份与整数手数换算，展示残余敞口；实际采购与KC的基差、汇率另行记录。
4. 现金流：逐日结算、初始及追加保证金、手续费、滑点、换月与资金压力情景。
5. 验证：按时间推进的样本外测试；处理预测窗口重叠；保存预测发布时输入、数据截止时间、参数与版本；逐段持仓计提盈亏。
6. 比较不套保、经企业确认的固定政策与动态政策的采购净成本、预算偏差、极端成本和保证金峰值；无稳定增益时维持基础政策。

业务政策、采购批次与现金约束尚未提供，因此本分支不声称已完成可实盘系统。

## 第二阶段：已实施的预测诊断修正

- 横盘方向不再自动判对，严格比较 up/flat/down。
- 情景记分卡分别披露可复盘样本和有效概率样本；校验三类概率、排除重复日期和非6–8日的周度配对。
- 对相同有效样本计算均匀、固定25/50/25及过去结果频率三个基准；历史频率使用每类一个伪计数平滑，当前结果在评分后才计入。
- 次期周报价格仍只是实际结果代理，未证明对应第五个交易日收盘；因此 has_skill 和 calibration_validated 均为 false，不能触发自动概率收缩。
- shrink_w 继续表示原预测保留比例，避免静默反转配置含义；关闭自动收缩，独立校准验证后才允许显式有效权重。验证异常时保持关闭。
- 中英文 HTML、Markdown 和文本报告显示样本口径、两个新增基准及验证局限。

第二阶段之后继续实施下述第三阶段；真实采购批次、结算日和企业政策审批尚待接入。

## 第三阶段：已实施的敞口、资金预算与账务修正

- KC 每手从误写的37.5吨修正为37500磅，即17.009713875吨。其他合约尺寸仍可显式传入。盈亏按持仓吨数换算为磅，价格单位为美分/磅。
- 统一纯函数按采购量减已定价量计算未定价敞口，取整数手数，报告实际覆盖比例和残余吨数。目标是该批次总仓位，不是追加指令。
- 输入保证金预算后，按账户权益及双边手续费预留限制手数。不配置每手保证金时，模拟盘禁止开仓；回测允许作为未受资金约束的研究对照，并返回 margin_constrained=false。保证金数额是用户输入，不自动冒充交易所实时要求。
- 模拟盘不再强制最少一手、不会覆盖未平仓头寸；修正吨数换算、平仓原因字符串和缩仓至不足一手的行为。盯市显示保证金缺口；仍是进程内模拟账户，不是真实结算银行账或重启恢复系统。
- 回测按每个被观测月份模拟一批月初未定价采购，于该月最后一根观测bar采购定价并平仓。采购量使用实际模拟月份，不再固定24个月。部分月份也算一个模拟采购批次。
- 静态与动态策略使用独立资金账户；持仓每日累计盈亏，调仓与最终平仓不重复计入；每条交易腿计费，月内目标变动实际调仓。无套保账户不再混入其他策略手续费。
- 新闻时间可落在bar之间；仅在其发布时间之后的bar执行，不用同bar消息即时成交。仍依赖源timestamp的真实可用性。
- 旧战绩页和预测复盘不再凭涨跌或中性仓位判定套保有效；效果指标返回None并展示待核验。

### 使用与边界

模拟盘先设置 `margin <每手美元保证金预算>`、`tons <本期采购吨数>`、`priced <已定价吨数>`，再输入 `ratio <目标比例>`。无行情时先用 `price <美分/磅>` 显式输入模拟价格。

这些是执行前的基础约束，不代表具备实盘条件。尚未实现真实批次/合约月份匹配、交易所动态保证金、滑点与实际换月、基差/汇率风险、外部资金划拨、审批及订单接口。回测的现货和期货使用同一价格序列，不应作为实际进口采购效果证明。

## 第四阶段：批次与合约绑定、基差及汇率情景

新增 PurchaseBatch 领域对象、batch_plan/stress_batch/preview_batch 与JSON预览命令。只支持明确以KC定价的阿拉比卡批次；不把罗布斯塔或其他定价方式直接映射到KC。合约月份采用YYYY-MM，必须是3/5/7/9/12月；退出截止日由用户从经纪商/交易日历提供，严格早于交割月且晚于评估日。浮动采购不得使用已过期的定价日。

模拟盘校验明确合约ID、报价与批次快照一致；持仓绑定batch_id与contract_id，不允许把另一批次、另一合约或未分配头寸静默复用。开平仓叙事携带批次和合约标记。当前为单批次、进程内模拟，不包含多批次组合、重启头寸恢复和交易所订单。

压力情景保留已定价数量的锁定单价，KC变动仅作用于未定价采购；固定基差不随基差冲击变化。全部采购假设尚未付款，现货与期货终端美元现金流以同一情景汇率换算，因而锁价采购仍有汇率风险。KC残余、基差与汇率三项成本变化加总等于净成本变化。此模型不处理不同结算日期、外汇对冲、税费运费或融资费用。

政策参考编号仅用于追溯，并未接入审批验证；executable表示数量/预算条件通过，不是下单授权。演示JSON中的市场数值和日历均为合成示例，使用真实业务时必须替换。

## 第五阶段：多批次共享资金与持久化

新增 PortfolioPaperEngine 和 cli.paper_portfolio。SQLite账户状态与逐操作审计在同一事务提交；写审计失败则全部回滚。每次操作先读取数据库最新状态，BEGIN IMMEDIATE 串行化写入，避免两个连接重复使用同一资金。

初始权益仅在账户首次创建时设定，重启不能借此重置亏损。账户现金保存已实现盈亏和手续费；权益加计全部持仓按所提供行情估算的未实现盈亏。所有开放批次共同占用保证金和退出手续费预算，新增仓位另预留开仓和退出费用。

显式减仓和平仓先执行，然后按输入批次顺序分配新增手数。这个顺序就是用户提供的资金优先级，不是优化器推断出的最优配置。未提供的批次保留；但其合约报价和保证金必须一并输入，不能从资金预算中漏掉。

操作编号在账户内唯一，相同编号与相同输入返回原始结果且不再次记账；同编号不同输入会报错。已保存的结果是那次操作的快照，重试返回的快照不表示当前最新状态，可通过 snapshot() 获取最后保存的账户状态。

出现保证金缺口和超期持仓时输出提示，未授权自动强平。报价按用户提供的评估日校验，并非实时抓取或经纪商确认；审批、外部成交、真实结算现金划拨、报价时分秒校验和多币种保证金尚未实现。旧单批次记录不会自动混入新组合账户。

### 逾期持仓的账户级开仓限制

多批次模拟账户在减仓后检查所有剩余持仓：到达退出期限，或超过点价日期时，暂停整个账户的新增仓位。仍可估值、显式平仓和减少有效批次的目标仓位；不自动强平。清理全部逾期持仓后，同一操作可按原有资金约束开仓。

返回值以 `risk_blocked` 与 `blocking_batch_ids` 解释计划拦截原因，`cash_limited` 单独表示资金不足。修改输入中的日期不会消除已有逾期持仓的限制；该持仓的原点价日期及退出期限保留，需显式平仓处理。账户状态持久化 `additions_blocked` 和阻塞批次列表。此限制仅适用于多批次模拟账户。

### 逾期后的显式部分减仓

`sync_batches` 和 `cli.paper_portfolio` 的 JSON 输入支持 `reduce_to_contracts`，例如 `"reduce_to_contracts": {"lot-1": 1}` 表示将已有批次减至 1 手（不是卖出 1 手）。目标为 0 表示全部平仓。此入口不需重新提交批次资料，保留原始日期及采购信息，因此逾期后也可部分减仓。

目标必须为非负整数，且不得超过当前手数；未知批次、同批次同时调整/平仓/减仓均拒绝。仍要求全部持仓合约的当日价格及保证金，并执行原有事务、操作编号去重和审计规则。剩余逾期持仓继续阻止新增仓位。该操作只调整模拟期货仓位，不表示现货采购数量或点价状态改变。

### 模拟账户请求的严格解析

多批次 CLI 在打开数据库前拒绝重复 JSON 字段（包括嵌套批次键）、NaN/Infinity/溢出浮点数、未知顶层字段，以及错误的集合类型。字段拼写错误不会再被静默忽略。`reduce_to_contracts` 必须是 JSON 对象；Python API 接受映射或默认的 None，不再将 False、空列表或键值对列表自动转换为减仓请求。拒绝此类请求不会产生交易或审计记录；新账户也不会因 CLI 解析错误而创建。

### 多批次模拟交易预览

已有账户可使用 `PortfolioPaperEngine.preview_batches`，或在原 `cli.paper_portfolio` 命令后加 `--dry-run`。预览无需 `--operation-id`，即使传入也不会消耗该编号；数据库和账户必须已存在。CLI 通过 SQLite 只读连接打开数据库，不创建账户或修改表结构。

返回 `mode: PREVIEW_NO_ORDER`、`base_version`、`projected_state`、`proposed_trades` 及计划与拦截原因；不保存持仓、现金、估值或审计记录。预览与执行共用计算及风控流程，从一致的数据库快照计算。它不预留资金，也不是交易授权或可锁定的成交报价；后续执行按最新账户状态重新检查，结果可能变化。预览中的 projected_state.version 是假设执行后的版本，不代表已写入。

```sh
python -m cli.paper_portfolio docs/examples/paper-portfolio.json \
  --db ~/.arbor/portfolio-demo.db --account demo \
  --as-of 2026-10-30 --dry-run
```
